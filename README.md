# 岁时有色

二十四节气 × 中国传统色。每个节气配一种颜色，再配上三候、习俗、时令吃食、一首诗和一幅古画；整页的颜色随节气换。

Vue 3 + TypeScript + Vite，纯前端，没有后端和数据库。

## 页面

用 hash 路由，网址形如 `https://example.com/#/term/lidong`。

| 路径 | 页面 |
| --- | --- |
| `#/` | 首页：岁时轮（二十四色环，点一段进入节气）和按四季分组的节气目录 |
| `#/term/<slug>` | 节气页，如 `#/term/lichun`；`slug` 是去掉声调的拼音。← / → 键翻到上一个、下一个节气 |
| `#/palette` | 色谱：二十四色，可按四季筛选，按节气顺序或色相排序，点击复制色值，并标出相近的色 |
| `#/about` | 关于：色名与取色、画作来源与许可、字体、节气日期的算法、已知的局限 |

## 运行与构建

需要 Node 20.19+ 或 22.12+。

```bash
npm install
npm run dev      # 开发服务器，默认 http://localhost:5173
npm run build    # vue-tsc 类型检查 + 构建到 dist/
npm run preview  # 本地预览 dist/
npm run thumbs   # 重新生成首页笺面小图（换了古画才需要；要装 Python 和 Pillow）
npm run fonts    # 重新生成“岁时宋”字体（改了页面上的文字之后需要，见下面“字体”；要装 Python）
```

项目里没有测试框架，`npm run build` 里的类型检查是唯一的自动检查。构建本身不需要 Python：生成好的字体已经放在 `src/assets/fonts/`。

## 数据在哪里

内容都写在 `src/data/` 的四个文件里，页面是从它们生成的。

| 文件 | 内容 |
| --- | --- |
| `terms.ts` | 二十四节气本身：名称、拼音、黄经、节气色（名称、拼音、色值）、两句色彩意象、三候、所属季节。也有“今天是哪个节气”的计算（`termOfDate`） |
| `solarTermDates.ts` | 2024–2040 年每年二十四个节气的交节日期（北京时间） |
| `content.ts` | 每个节气的正文：一句话简介、两段说明、三候的白话解释、习俗、时令吃食、一首诗、色名的由来。顺序与 `terms.ts` 相同，都是自立春起 |
| `paintings.ts` | 二十四幅古画的出处，以及每个节气配哪一幅、画里取色的位置与色差 |

其余：`src/utils/color.ts` 是颜色计算（对比度、混色、CIEDE2000 色差、由节气色推出页面用的深色与浅色）；`src/composables/useTerm.ts` 把当前节气的颜色写成 CSS 变量，整页换色就是从这里来的。

### 改一个节气的颜色或文字

- 色名、色值、意象、三候：改 `terms.ts` 里 `ROWS` 对应的一行。
- 正文、习俗、诗：改 `content.ts` 里对应的一项。
- 改了色值，要回头看一下：对比度（页面标题用的深色是自动算的，不用管）、色谱页里的相近色提示（也是自动的）、**以及 `public/og-cover.png` 要重新画**（见下面“分享卡片”）。
- 配画时记在 `paintings.ts` 里的 `hex` 与 `de`（画里取到的颜色、与节气色的色差）是改色值之前算的，改了色值后需要重新算。

### 换一幅画

1. 从克利夫兰艺术博物馆的开放获取藏品下载图片：`https://openaccess-cdn.clevelandart.org/{藏品号}/{藏品号}_web.jpg`（图像为 CC0），存到 `public/album/{藏品号}_web.jpg`。
2. 在 `paintings.ts` 的 `PAINTINGS` 里加一项出处（藏品号 `acc`、画家、朝代与年代、作品名、中文题名、馆方英文题名、质地、网页图的像素宽高 `w`/`h` 等，字段见文件里的 `Painting` 类型）。
3. 在 `PLATES` 里把对应节气的 `acc` 指向这幅画，并填：为什么配这幅（`why`）、取色点在图上的位置（`x`、`y`，百分比）、取到的颜色（`hex`）、与节气色的色差（`de`，用 `utils/color.ts` 的 `deltaE` 算）、竖幅小图的焦点（`focus`）。

取色点目前是手工找的，仓库里没有自动取色的脚本。

### 延长节气日期表

`solarTermDates.ts` 只有 2024–2040 年。表之外的年份，`termOfDate` 会退回到每个节气自带的固定月日，最多差一天，页面不会报错，但“今日节气”在交节日前后可能错一天。

要加年份：按太阳视黄经每到 15° 的整数倍交节，用 Meeus《天文算法》第 25 章的公式求出时刻，换成北京时间取日期，再用另一个独立的实现核对，一致后把新的一年按“月 × 100 + 日”追加进表里。生成脚本没有放进仓库。

## 字体

全站只用一个字体：**岁时宋（Suishi Song）**，本站自制，只含站内用到的约 1,500 个字，400 与 900 两个字重（CSS 里写 500 的落到 400，写 600 的落到 900）。正文、标题、诗、西文和数字都是它，系统宋体只兜底思源宋体里没有的极少数字（目前是 Δ雊鴠鴽）。

### 设计

以思源宋体（Noto Serif SC）为骨架，`scripts/build_font.py` 统一改造每一笔，取“铅字压印”的墨感：

1. 骨架取得比目标字重细一档（400 用思源宋体 300，900 用 800）；
2. **积墨**：轮廓先向外扩一圈再收回同样的量（形态学闭运算），笔画相交、转折的内角被填成小圆弧，像墨在交接处积起来；
3. **晕开**：再整体向外扩一小圈，宋体的三角饰脚、起笔收笔、点的尖都变成同一半径的圆角，横竖对比被拉近一点；
4. 汉字字面横向收窄到 96%（字宽不变），字距略松，适合长段的诗和说明；
5. 西文、数字取同一骨架、同样处理，所以全站只有一个字族。

两个字重的参数在脚本顶部的 `STYLES`：`(CSS 字重, 骨架字重, 晕开半径, 积墨半径, 文件名)`，单位是字体单位（字身 1000）。字体保留了竖排用的 `vert`，名字表里写明了改制自思源宋体和 OFL 许可。

### 什么时候要重新生成

改了会显示在页面上的任何文字之后。没重新生成的话，新字会退到系统宋体，页面不会坏，只是那几个字字形不同。

1. 文字改动大时，先更新扫描：`npm run dev`，在浏览器里打开页面，控制台运行 `await __scanFonts()`，结果写到 `scripts/font-chars.json`（只在开发模式里有这个函数）。它记录每个字出现在哪些页面、用哪个字重，分包靠它；只加了几个字可以跳过这步，新字会归到 `rest` 分包。
2. `npm run fonts`（即 `python scripts/build_font.py`）。它扫描 `src/` 下所有 `.ts`、`.vue` 和 `index.html` 里的字，生成字形、分包，写出 `src/assets/fonts/suishi-song-*.woff2` 和 `fonts.css`，旧的 woff2 会先删掉。在本机约 1.5 分钟。
3. `npm run build`。

`--ttf 目录` 另存整套 `.ttf` 预览；`--chars 字串` 只生成这几个字（试样用，不分包）；`--file-cost N` 是分包参数，默认 30000：越小文件越多、每页多下的无用字越少，越大则反之。

### 运行脚本需要什么

- Python 3 和 `pip install fonttools brotli skia-pathops`（在 Python 3.13、fonttools 4.62 上写的）。
- 先 `npm install`：脚本从 `node_modules/@fontsource/noto-serif-sc` 读思源宋体的字形。
- 生成的字体是生成物，**随仓库提交**，只构建站点的人不需要 Python。
- `scripts/subset_fonts.py` 是旧方案的裁剪脚本，现在只被 `build_font.py` 借用分包算法，不要单独运行它。

### 分包与体积

每个字重的整套约 350 KB（400）和 400 KB（900），一页用不到这么多，所以拆成 45 个文件，`unicode-range` 精确到字、互不重叠，浏览器只下载页面上出现了字的那几个。分法按“字出现在哪些页面”聚类，使全站总下载量最小：每天的首页都出现的字（和全部 ASCII）归 `core`，其余按用途命名 `page-N`、`mix-N`、`palette`、`about`，扫描里没见过的字归 `rest`。

实测每页下载的字体约 320–335 KB（6–7 个文件）。旧方案只给标题和西文用网页字体，每页 52–82 KB，正文用系统字体；换成全站一个字体，代价就是这多出来的约 250 KB，性能见“已知的局限”。

构建时 `vite.config.ts` 把 `.woff2` 排除在 base64 内联之外，并给 `suishi-song-900-core` 加 `<link rel="preload">`（首页大标题用它）。400 的核心文件（53 KB）不预加载：试过两个都预加载，它和大标题抢带宽，首屏反而更慢。

## 滚动质感

没有用 GSAP，只用了 [Lenis](https://github.com/darkroomengineering/lenis)（gzip 约 5 KB，首屏之后才懒加载）加一个自写的视差指令，代码都在 `src/utils/motion.ts`。

- **平滑滚动**：只在“有鼠标 / 触控板（`hover: hover` 且精细指针）并且没开减弱动效”时启用；触屏保持系统自带的惯性。全屏菜单把 `html` 设成 `overflow: hidden` 时 Lenis 会自动停住。页内跳转（`scrollToId`）、回顶部、换页回顶都走 `motion.ts`，没启用 Lenis 时退回浏览器自带的平滑滚动。
- **视差**：`v-parallax="系数"` 把元素相对视口中心的偏移写进 `--py`，样式用 `translate` 去吃它，不会和悬停缩放的 `transform` 打架。现在用在两处：节气页的大字标题、首页目录里的古画缩略图（图片上下各留 8% 余量）。减弱动效时指令不生效，`--py` 缺省为 0。

- **渐显（`v-reveal`）可重复、可逆向**：元素完全滚出视口后收回，再进来重新播。从上边出去的停在上方（`reveal--above`），往回滚时自上而下落进来；从下边出去的向下滚时自下而上升起。视差本身跟着滚动位置走，往回滚自然是反向的。减弱动效时全部直接显示。

## 部署

`npm run build` 之后，把 `dist/` 整个放到任意静态空间即可（GitHub Pages、Netlify、对象存储、自己的 Nginx 都行）。用的是 hash 路由，**不需要服务器配置回退规则**。

- **放在子目录**：构建前在 `vite.config.ts` 里设 `base`，例如 `base: '/suishi/'`。画作路径、路由、图片都跟着 `base` 走。
- **分享卡片的网址**：微信、X、Telegram 等抓取分享信息时要求 `og:image` 是绝对网址。构建时设置环境变量 `VITE_SITE_URL` 为首页的完整网址，构建就会补上 `og:image`、`twitter:image`、`og:url` 和 `canonical`：

  ```bash
  VITE_SITE_URL=https://example.com/suishi/ npm run build
  ```

  也可以写进 `.env.production.local`（`*.local` 已经被 `.gitignore` 忽略）。不设置也能构建，只是分享出去抓不到图片，也没有 `og:url` 和 `canonical`。

### 分享卡片

全站只有一张封面图 `public/og-cover.png`（1200 × 630，二十四色环和站名），所有页面分享出去都是这一张。图是用站点自己的二十四个色值和字体画的静态文件，**改了节气色之后需要重画**，仓库里没有生成它的脚本。

## 已知的局限

- **没有每个节气自己的分享卡**。hash 路由下所有页面是同一个 `index.html`，爬虫看不到 `#` 之后的部分，也就拿不到各节气自己的标题和图。想做的话要改成 `createWebHistory`，并在构建时为每个节气预渲染一个 `index.html`（部署环境要支持目录式的静态页），这是单独的一项工作。
- **没有 JavaScript 时只显示一段说明**和二十四个节气名。
- **色值是为屏幕拟定的近似值**，不是传统色的权威标准；色名来自传统色名，具体用哪个色值各家并不一致。
- 页面换色的动画、纹理在不同浏览器和设备上的观感可能有差别，没有在所有环境上逐一验证。
- **换成全站自制字体后，模拟降速下各页在 82–86，真降速（`--preset=perf`）下 58–74，都比换字体前低。** Lighthouse v12、移动端、对本机 `npm run preview` 测，只代表这台机器。
  - 默认的“模拟”降速：首页 83，节气页（立冬）86，色谱页 86，关于页 82。换字体前（标题和西文用网页字体、正文用系统字体）是 91–98。
  - `--preset=perf`（真的在浏览器里降速）：首页 63–67，节气页 51–74，色谱页 55–58，关于页 56–61。换字体前是 63–77。同一页两次能差 10 分以上，只能看区间。
  - 掉分的原因是字体本身：每页要下约 320 KB 字体（以前 52–82 KB），而且正文字体换上来时整页要重排一次，真降速下总阻塞时间在 0.65–1.8 秒。最大内容绘制（首页大标题）卡在渲染延迟上。试过但没用：把曲线拟合容差从 2 放宽到 5，文件只小 6%。有用的一处：只预加载 900 的核心文件，真降速下首页和节气页各回升几分。
  - 换字体前做过对照实验：**即使完全不用自定义字体，真降速也只有 80 出头**（色谱页强制用单一系统字体 80–83 分），瓶颈是第一次排版时的中文字体匹配。要回到 90 以上，只能让正文退回系统字体，只给标题用岁时宋，那就不再是“全站一个字体”。
  - 其他有效的改动：节气页题头之后的各段在首屏画完约 0.8 秒后才挂载（`TermView.vue` 的 `rest`，带 `#` 锚点时立即挂载）；去掉了 `PrefaceSection.vue` 里的 `text-wrap: pretty`（对中文排版很贵）。
  - 本机 `vite preview` 是 HTTP/1.1，线上用 HTTP/2 的表现没有验证。

## 来源与许可

- **画作**：克利夫兰艺术博物馆（The Cleveland Museum of Art）开放获取藏品，图像为 CC0。每一幅的藏品号、画家和馆方页面都列在“关于”页。
- **字体**：岁时宋由思源宋体（Noto Serif SC，取自 `@fontsource/noto-serif-sc`）改制，按 OFL 1.1 的要求换了名字，随思源宋体一起以 OFL 1.1 发布。只发布站内用到的字，不是整套字体。
- **节气日期**：按天文算法求得，并与独立实现逐项核对过 2024–2040 年的全部 408 项。
